# Fuzzing framelink

The decoder reads bytes from an untrusted wire. It must never crash, read or write out of bounds, hang, or deliver a frame that fails its own round trip, whatever it is fed. These harnesses check that.

## Harnesses

| Harness | Input | Checks |
|---------|-------|--------|
| `fuzz_decoder` | Raw byte stream. The first byte selects the feed chunk size and how often the inter-byte timeout fires | No ASan or UBSan error. Every delivered frame is within `FL_MAX_PAYLOAD` and re-encodes to a frame that decodes back to itself. Frame counter matches callbacks. No partial frame left after the final timeout |
| `fuzz_roundtrip` | `TYPE SEQ SPLIT PAYLOAD...` | Encoding then decoding, split at any point, returns exactly one identical frame with no errors counted |

Both are plain `LLVMFuzzerTestOneInput` functions, so they work with libFuzzer, and with AFL++ through `standalone_main.c`.

## Running with libFuzzer

Requires clang on Linux, macOS or WSL2.

```sh
CC=clang cmake -B build-fuzz -DFL_FUZZ=ON -DFL_BUILD_TESTS=OFF -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build-fuzz

# Work on a copy so the committed seed corpus stays small and reviewed.
mkdir -p /tmp/fl-corpus && cp fuzz/corpus/decoder/* /tmp/fl-corpus/
./build-fuzz/fuzz/fuzz_decoder /tmp/fl-corpus \
    -dict=fuzz/framelink.dict -max_total_time=3600 -print_final_stats=1
```

Use `-jobs=N -workers=N` to run several processes in parallel.

## Running with AFL++

```sh
CC=afl-clang-fast cmake -B build-afl -DFL_BUILD_TESTS=ON
cmake --build build-afl --target fuzz_decoder_replay
afl-fuzz -i fuzz/corpus/decoder -o /tmp/afl-out -x fuzz/framelink.dict -- ./build-afl/fuzz/fuzz_decoder_replay
```

The `_replay` binaries read one input from stdin when run without arguments, which is what AFL++ expects.

## The seed corpus

`fuzz/corpus/` holds hand-picked seeds generated by `make_corpus.py` from the shared test vectors. Every normal build replays them through the `_replay` binaries as part of `ctest`, so they also act as regression tests. CI checks that the committed corpus matches the generator.

When the fuzzer finds a crash:

1. Fix the bug.
2. Minimise the input with `-minimize_crash=1`.
3. Add the minimised input to `make_corpus.py` as a named seed, so it is replayed on every build from then on.

## Reporting results

Published iteration counts go in [docs/MEASUREMENTS.md](../docs/MEASUREMENTS.md#6-fuzzing), with the clang version, wall time and date. CI runs each harness for 60 seconds on every push and writes the execution count to the run summary.
